# Руководство: если Вы — автор задачи

Данная часть руководства была частично адаптирована из [qazcho-latex](https://github.com/Beyond-Curriculum/qazcho-latex/)-репозитория.

## Как начать оформлять задачи?

1. Зарегистрируйтесь на сайте overleaf.com. Этот ресурс позволяет быстро компилировать код LaTeX и видеть как будет выглядеть оформление Вашей задачи.
2. Скачайте последнюю версию шаблона заданий, решений и бланка ответов. Все три шаблона объединены в одном .zip-файле `shared/author-template.zip`.
3. На сайте overleaf.com нажмите на кнопку New Project и выберите опцию Upload Project.
4. Загрузите файл `author-template.zip`.
5. Как только откроется проект, сайт попытается скомпилировать его. Вы увидите ошибки компиляции — не пугайтесь. Нажмите на кнопку Menu в левом верхнем углу. Откроется боковое меню. Найдите параметр Compiler — по умолчанию выбран pdfLaTeX. Выберите XeLaTeX, а также TeX Live version 2024, и нажмите на кнопку Recompile. Теперь вы увидите пдф версию вашего файла.

## Как работает LaTeX?

Здесь инструкции к стандартным LaTeX командам будут несильно отличаться от таковых у QazChO, так что рекомендую прочесть секцию с таким же названием данного раздела [у них](https://github.com/Beyond-Curriculum/qazcho-latex/#%D0%BA%D0%B0%D0%BA-%D1%80%D0%B0%D0%B1%D0%BE%D1%82%D0%B0%D0%B5%D1%82-latex).

## Работа с шаблонами и общие команды для шаблонов

Откройте Ваш проект с шаблоном. Файл `main.tex` (тот, с которого компилируется весь комплект), будет содержать в самом начале следующую команду:
```
\documentclass
[
  language=ru,      % ru | kz
  grade=11,         % any integer
  tour=theory,      % theory | experiment
  type=problems,    % problems | solutions | marking | jury
  style=respa       % respa | ipho
]{olympiad}
```
Данная команда читает код с `olympiad.cls`. В комментариях указаны возможные опции для редактирования. В зависимости от того, какую задачу хотите составить (язык/класс/тур), не бойтесь менять соответствующие ключи. Последний ключ `style` указывает на выбор дизайна — формат `respa` выглядит так же, как и в `shared/example/`, а формат `ipho` во многом был адаптирован из `.tex`-файлов самих комплектов IPhO (в основном, версия 2025 года). Если оформляете длинную задачу межнарного стиля, то выбирайте `style=ipho`.

Про команды `\include` и `\input` можете прочесть в [этом гайде от Overleaf](https://www.overleaf.com/learn/latex/Management_in_a_large_project). Вкратце, эти команды вставляют в основной файл `main.tex` код из других нужных файлов. Отличие в том, что команда `\include` вставляет разрыв страниц перед тем, как вставить содержание в документ.

В дальнейшем, оформляя задачу, берите пример с того, как была написана респа 2026 года, в папке `shared/example/`.

### Оформление условия задачи (`tour=problems`)

Все команды ниже затрагивают то, что должно принадлежать `problem.tex`.

#### Заголовок задачи: `\problem{...}{...}`

Для начала задачи в файле `problem.tex` начинайте с команды `\problem{problem_name}{points}`. 

#### Заголовок подзадачи: `\subproblem{...}{...}`

Аналогичная вещь. Имейте в виду, что для `style=respa` эти команды используются в основном для того, чтобы оформлять солянку (задача, состоящая из трёх независимых подзадач). Для `style=ipho` эти команды выступают как подзаголовок задачи — нужно **как минимум один раз** использовать его для адекватной нумерации дальнейших пунктов условия (так, в целом, и оформляются межнарные задачи стиля IPhO).

#### Часть задачи: `\part{...}`

Эта вещь носит косметический характер. `\part` чаще используется для `style=respa`, и лишь иногда, для дальнейшего разбиения подзадачи на подзаголовки, для `style=ipho`.

#### Условия задач: `task`

Допустим, Ваша задача концептуально длинная, и состоит из нескольких пунктов. Тогда для создания пункта задачи нужно делать следующее:
```
\begin{task}
    \item Это — пункт вопроса задачи.
    \item Это второй пункт.
    \item ...
\end{task}
```
Имплементация такая же, как в нумерованных списках `enumerate`. Если Вы планируете открыто указывать количество баллов на каждый подпункт (работает только для `style=ipho`), то:
```
\begin{task}
    \item[0.2] Этот пункт весит 0.2 балла.
    \item[0.8] Этот второй пункт весит 0.8 баллов.
    \item К этому пункту количество баллов не указывается.
\end{task}
```
Если Ваша задача концептуально короткая и под стиль `style=respa`, но всё равно имеет 2-3 вопроса, можно оформить `task` с опциональным ключом `type`:
```
\begin{task}[type=subproblem]
    \item ...
\end{task}
```
Вместо порядкового номера задачи и его подпункта будет алфавитная нумерация жирным текстом: **(a)**, **(b)**, ... . Ключи `type=alternative` и `type=alphabetical` работают абсолютно так же. Стиль `style=ipho` игнорирует `type=subproblem` и возвращает к стандартному дизайну пунктов условия.

#### Изображения

Есть два способа вставлять изображения.

Стандартный: использовать `figure` или `wrapfigure` (последнее требует пакадж `wrapfig` — уже загружен в `olympiad-layout.sty`):
```
\begin{figure}[H]
  \centering
  \label{mycustomlabel}
  \includegraphics[width=0.8\linewidth]{image1}
\end{figure}
```
Аргумент `H` нужен, чтобы изображение поместилось в порядке, указанном в коде.
```
\begin{wrapfigure}{r}{0.4\textwidth}
    \centering
    % Keep image width slightly smaller than environment width to avoid overlapping text
    \includegraphics[width=0.38\textwidth]{example-image}
    \caption{A wrapped figure.}
    \label{fig:wrapped_example}
\end{wrapfigure}
```
Здесь она создаёт картинку справа от текста с шириной `0.38\textwidth`. В обоих примерах можно менять ширину через `width=`, а также `\label{any_text}`. Если использовать `\label`, то в самом файле можно ссылаться на картинку: например, писать `... указано на Рис. \ref{any_text}`. Директорий к картинке рассчитывается относительно расположения файла `main.tex`. Если в Вашем проекте, допустим, есть папка `figures`, тогда нужно вводить `figures/image1`.

Второй способ: кастомные команды, которые были написаны для данного шаблона для упрощения этих двух "тяжёлых" примеров сверху (они содержатся в `olympiad-layout.sty`):
- `\cpic{fraction_of_linewidth}{image}[Caption]`. Размещает картинку по центру; в качестве первого аргумента принимает любое дробное число от 0 до 1. Пример: `\cpic{0.8}{figures/image1}[Текст под картинкой]`.
- `\cpics{fraction1}{image1}{fraction2}{image2}[Caption]`. Размещает две картинки рядом друг с другом; первые два аргумента аналогичны для `\cpic` по отношению к первой картинке; следующие два аргумента аналогичны для `\cpic` по отношению ко второй картинке.
- `\pic{num_lines}{R/r/L/l}{num_pt}{fraction_of_linewidth}{image}[Caption]`. Чуть более сложная для запоминания команда: воспринимайте так, что к `\cpic` "спереди" добавляются три новые команды, отвечающие за размещение картинки
    - Первый аргумент принимает любое натуральное число. Оно показывает, сколько строк текста размера `\normalsize` нужно, чтобы картинка поместилась на всю свою высоту
    - Второй аргумент принимает либо `R` (или, что то же самое, `r`) либо `L` (или, что то же самое, `l`). Оно показывает, с какой стороны (справа или слева) размещать картинку.
    - Третий аргумент принимает любое целое число, и показывает, на сколько единиц `pt` нужно сместить по высоте картинку. Положительные значения — сдвиг вниз, отрицательные значения — сдвиг вверх. На практике всегда нужно указывать лишь небольшое неположительное значение (от `-6pt` до `0pt`).

Во всех случаях есть опциональный аргумент (опциональный = требует квадратных скобок вместо фигурных), в который можно ввести текст для caption. _Если был использован caption_, то к картинке автоматически генерируется `\label{fig:n.m}`, где под `n` понимается номер задачи, а под `m` порядковый номер картинки внутри задачи (в подсчёт **не** входят картинки, у которых отсутствует caption).

Чтобы сослаться на картинку, команда `\ref` не сработает — для этого введена кастомная команда `\figref{m}`, где `m` — тот же самый порядковый номер картинки. Технически говоря, `\figref{m}=\ref{fig:n.m}`. Это помогает Вам ссылаться на изображения, не вникая в порядковый номер задачи внутри комплекта (что облегчает работу редакторам, когда надо будет раскидывать задачи в определённом порядке). **По этим причинам, сильно рекомендуется применять второй способ с кастомными командами.** Если Вы хотите функционал, который не поддерживается вторым методом, то используйте первый метод.

_Known issue:_ пока что нет поддержки многостраничных `.pdf`-файлов, которые содержат, к примеру, `ipe`-метаданные. Будет введено позже.

#### Единицы измерения

Для единиц измерения используется пакет `siunitx`. Можно использовать команды `\qty{}{}` и `\unit{}`. Примеры использования:
```
Плотность воды равна $\rho = \qty{1000}{\kilo\gram\per\meter\cubed}$
Константа скорости равна $k_1 = \qty{0.0042}{\liter\per\mole\per\second}$

Плотность воды равна $\rho = 1000~\unit{\kilo\gram\per\meter\cubed}$
Константа скорости равна $k_1 = 0.0042~\unit{\liter\per\mole\per\second}$

Скорость света равна $c = \qty{3e8}{\meter\per\second}$
Скорость света равна $c = \num{3e8}~\unit{\meter\per\second}$
```

В шаблоне, Вы можете обратить внимание на файлы `olympiad-units-{base,gost,ru,kz}.sty`. Они содержат перевод на русский/казахский единиц измерения пакаджа `siunitx`. (Многие вещи имеют одинаковый перевод на обеих языках, так что они лежат в `...-gost.sty`, где под `gost` имеется в виду принятый по СНГ стандарт ГОСТ — но это, конечно же, условности.) Для тех, кто раньше пользовался моим шаблоном олимпиад до весны 2026 года, была сохранена отныне-не-используемая команда `\pu{...}` (pu = physical unit). Она всё ещё имеет немного преимуществ относительно `siunitx` (но гораздо больше недостатков). Примеры использования:
```
Гравитационная постоянная $G=\num{6.67e-11}\pu{Н*м2/кг2}$
Магнитная постоянная $\mu_0=4\pi \cdot 10^{-7} \pu{Гн*м-1}$ % \num{4\pi e-7} приведёт к ошибке!
```

### Оформление решения задачи (`tour=solutions`)

Все команды ниже затрагивают то, что должно принадлежать `solution.tex`. Для Вашего шаблона **оставьте** `tour=problems` внутри `\documentclass`. Этот ключ нужен редакторам для правильной компиляции конечного комплекта. Вы в любом случае сможете вставить `\input{solution.tex}` внутри `main.tex`.

#### Заголовок задачи: `\solution{...}{...}`

Аналогично, в `solution.tex` начало решения оформляйте с `\solution{problem_name}{points}`. Убедитесь, что названия и баллы сходятся с `\problem{...}{...}`.

#### Заголовок подзадачи: `\subsolution{...}{...}`

Аналогичная вещь. Убедитесь, что названия и баллы сходятся с `\subproblem{...}{...}`.

#### Начало решения пункта: `\tasksol`

Данная команда не принимает аргументов. Она автоматически рассчитывает и выдаёт жирным текстом `номер_задачи.номер_пункта`. **Обязательно** используйте `\tasksol`, поскольку это нужно будет для структуризации марк-схем.

#### Критерий для марк-схемы: `\criterion[...]{...}`

Эта команда **не видна** в файле решения. Однако она **структурно важна** для оформления марк-схем. Во второй аргумент в фигурных скобках `{...}` нужно писать обычный текст, объясняющий условие получения балла. Первый аргумент в квадратных скобках содержит разное количество ключей. Пример использования:
```
\criterion[type=penalty, points=-0.2]{Не показаны попарные суммы без объяснения}
\criterion[points=0.8]{Ответ в интервале $n\in[3.8,\ 4.1]$}
\criterion[type=remark]{\textbf{0.2 + 0.2 } за верную амплитуду вектора и зависимость фазы от координат}
```
В первом аргументе `\criterion` есть два разных ключа:
- `type=` — принимает аргументы `penalty`, `remark`, `alternative`. Все три значения работают одинаково — здесь просто дело вкуса самого автора.
- `points=` — принимает число (положительное или отрицательное) **через разделительную точку** (не запятую). Технически, можно вписать что угодно (к примеру, `points=0,3/0,6`), но важность использования обычной десятичной дроби с разделительной точки будет объяснена на этапе марк-схем. 

#### Критерий для марк-схемы: `\begin{eq}[...] ... \end{eq}`

Эта команда **видна** в файле решения. Она имеет все стандартные свойства обычного `equation` environment, однако есть пару дополнительных введений.

- Как это было с captions в изображениях, `eq` автоматически генерирует `\label{eq:n.m}`, где `n` — номер задачи, а `m` — порядковый номер уравнения (только среди тех, которые используют `eq`). В таком случае обычный латеховский `\eqref` (который тоже модифицирован мной) может ссылаться на это уравнение через просто `\eqref{m}` (т.е., как и с изображениями, не ссылаясь на номер задачи, а только на авто-сгенерированный порядковый номер уравнения).
- К сожалению, здесь не получится использовать `\eqref` "по-старинке" (т.е. с кастомно указанным `\label` внутри `equation` энвайронмента). Аналогом этого служит `\OlympOldEqref{...}`.
- Весь контент данного уравнения будет впоследствии напрямую скопирован в марк-схему
- Порядок декларированных `\criterion` и `eq` **важен** — сгенерированная марк-схема будет последовательно считывать все эти критерии и уравнения один за другим.

Так же, как и `\criterion`, в квадратных скобках `eq` содержатся следующие ключи:
- `points=` — так же, как и в `\criterion`
- `numpoints=` — отдельно показывает, сколько баллов Вы хотите давать за числовое значение данного выражения. В марк-схеме создадутся две строчки вместо одной: первая покажет балл за само уравнение, вторая покажет балл за численное значение.
- `type=` — принимает значения `common`/`alternative`/`other`. Последние два работают одинаково; первая опция по сути бесполезна, так как `type=common` эквивалентен не указыванию `type` вообще. Опция `alternative` или `other` укажут критерий марк-схемы курсивом (в основном нужно при альтернативном методе решения задачи).
- `prefix=` — заменит префикс "Формула" на Ваш вариант (например, `prefix={Ответ}`).
- `tail=` — сразу после уравнения прибавит дополнительный текст в марк-схеме внутри той же строчки (часто нужно начинать с запятой, точки, или semicolon).
- `suffix=` — то же, что и tail (его псевдоним).
- `label=` — если не хотите использовать автосгенерированный `eq:n.m`, то `label` переопределит ключ на Ваше кастомное название. Нужно ссылаться через `\OlympOldEqref{...}`.
- `override=` — если значение не пустое, то марк-схема скопирует не уравнение внутри `eq`, а значение внутри `override`. Полезно, если в уравнении показана длинная логическая цепочка: например, `ax^2+bx+c=0 \implies x = (-b \pm \sqrt{b^2 - 4ac})/2a`, и ключом `override={x = (-b \pm \sqrt{b^2 - 4ac})/2a}` будет скопирована для оценивания только эта часть уравнения.

Примеры использования:
```
\begin{eq}[points=0.3, prefix={Численное значение}]
    t=\qty{9.67e11}{\s}\approx\num{30600}~\text{лет}.
\end{eq}

\begin{eq}[points=0.2, numpoints=0.2]
l = R_\odot\ab(\frac{T_s}{T_0})^4\approx\qty{1.67}{\mm}.
\end{eq}

\begin{eq}[points=0.3, override={D^2 = l_1^2+\dots+l_N^2+2\ab(\vec l_1\cdot\vec l_2+\vec l_1\cdot\vec l_3+\dots)}]
    D^2 = l_1^2+\dots+l_N^2+2\ab(\vec l_1\cdot\vec l_2+\vec l_1\cdot\vec l_3+\dots)=\sum_{i=1}^N l_i^2 + 2\sum_{i\neq j}\vec l_i\cdot\vec l_j,
\end{eq}

\begin{eq}[points=0.2, type=alternative]
    q(t)=\frac{\Delta I}{\omega}\sin(\omega t).
\end{eq}

\begin{eq}[points=0.3, numpoints=0.1, prefix={Ответ к \textbf{(a)}}]
    q = U_0\tau\sqrt\frac{2C}{L}=2.09\pu{мКл}.
\end{eq}
```

### Оформление марк-схемы

#### Марк-схемы: Теоретический тур

При условии, что все `eq` и `\criterion` были использованы корректно в `solutions.tex`, то в `marking.tex` нужно прописать ...

...

всего лишь `\showmarking`.

Эта команда считывает текст из `solution.tex`, генерирует таблицу на основе `eq`/`\criterion`. Она также просчитывает сумму баллов, игнорируя:
- Текст, который не является стандартным десятичным числом с разделительной точкой; к примеру, `0,6`, `1.0/1.5`
- Уравнение/критерий, имеющий `type=alternative`.

Это, однако, не окончательная версия марк-схемы. В самом деле, процесс здесь немного более сложен. Здесь появляются несколько концептуальных трудностей:
- Тяжело использовать `\multirow` внутри марк-схем для длинных задач с кучей подпунктов.
- Многие уравнения содержат пунктуацию как часть текста (например, `формула Пифагора гласит, что \begin{eq}a^2+b^2=c^2,\end{eq}` и она известна многим со школы.`). TeX-среда концептуально _не может_ отсечь trailing punctuation (те, кто работали над респой 2026, могут вспомнить об архаичной команде `\eq[]{}[]`).

Для этой цели был написан `extract-marking.py` в корневой папке репозитория.

##### Использование `extract-marking.py`

1. Скачайте `extract-marking.py` с репозитория.
2. Скачайте Ваш текущий `solution.tex` с Вашего Overleaf проекта
3. Нажимаете `Win`, потом прописываете `cmd`, нажимаете `Enter`, чтобы открыть командную строку;
4. Допустим, оба файла `extract-marking.py` и `solution.tex` находится на Вашем рабочем столе. Тогда пишете `cd Desktop`. Это откроет директорий рабочего стола;
5. Скрипт требует ввода в виде `python extract-marking.py <file.tex> <out_dir> [ru|kz]`. Пишете `python extract-marking.py solution.tex . ru`. Точка в качестве out_dir говорит "создай файл в том же месте, где я нахожусь, т.е. рабочий стол".
6. Создастся файл `solution_marking_ru.tex`. Скопируйте его содержимое и вставьте в `marking.tex` на Вашем Overleaf.

Если сложновато разобраться с инструкцией — Вы не обязаны это делать, но самое главное правильно оформите `solution.tex` (т.е. так, что `\showmarking` выдаёт в целом верную таблицу), и отдайте редактору свои файлы без готового `marking.tex`. Но если Вы проделаете эти вещи выше, Вы немного облегчите работу редакторам :)

#### Марк-схемы: экспериментальный тур

Здесь сохранена имплементация с респы 2026. Здесь не используются никакие `extract-marking.py`, никакие `\criterion`, и никакие `eq`. В основном это связано с тем, что решение эксперимента и его марк-схема практически не содержат ничего общего, а марк-схема имеет много текста для описания критериев. Пример с эксперимента респы 2026:
```
\begin{mse}
    \escheme{Проведено измерение ЭДС батареи}{0.5}
    \escheme{Найден ток при открытом диоде}{0.7}
    \escheme{Найдено сопротивление первого резистора}{0.5}
    \escheme{Найден ток при закрытом диоде, то есть при другой полярности}{0.7}
    \escheme{Утверждение и аргументация последовательного соединения диода и резистора к концам черного ящика}{1.0}
    \escheme{Утверждение и аргументация о том, что к выводам черного ящика могут быть соединены лишь диоды с резистором или ветви с конденсатором, обеспецивающие разрыв цепи}{0.6}
    \escheme{Описано поведение/наблюдение подтверждающее присутствие конденсатора}{0.5}
    \escheme{Описан метод измерения напряжения на выводе при разрядке конденсатора или нарисована соответствующая схема, разъясняющая ход эксперимента}{0.8}

    \blockbegin{Построена таблица зависимости $V(t)$. Баллы за измерения ставятся только если сами измерения и метод верные.}{1.8}{7}
        \bscheme{Измерено 15 и больше точек напряжения}{0.9}
        \bremark{Между 10 и 14 точками}{0.6/0.9}
        \bremark{Между 5 и 9}{0.3/0.9}
        \bscheme{Есть измерения при $t > \qty{20}{\s}$}{0.3}
        \bscheme{Есть измерения при $t < \qty{6}{\s}$}{0.3}
        \bscheme{Вычислены значения $\ln V$ для полученных точек}{0.3}
    \blockend

    \blockbegin{Построен график зависимости $V(t)$. Баллы за пункты \textbf{M10} и \textbf{M11} ставятся только если принят пункт \textbf{M9}.}{1.8}{4}
        \bscheme{Оси подписаны и оцифрованы}{0.5}
        \bscheme{Нанесены все точки в соответствии с таблицей}{0.9}
        \bscheme{Проведена сглаживающая кривая}{0.4}
    \blockend

    \blockbegin{Построен график в координатах $\ln V, t$}{2.3}{4}
        \bscheme{Оси подписаны и оцифрованы}{0.5}
        \bscheme{Нанесены все точки в соответствии с таблицей}{0.8}
        \bscheme{Кривая аппроксимирован прямой функцией}{0.5}
        \bscheme{Из графика найдены значения $k, b$}{2$\times$ 0.3}
    \blockend

    \escheme{Предложена и обоснована схема черного ящика}{1.3}
    \escheme{Формула \eqref{2}:  $\ln V = \ln V_0 \frac{R_1}{R_1+R_2} - \frac t \tau$}{0.8}
    \escheme{Найдено сопротивление второго резистора}{0.4}
    \escheme{Найдена емкость конденсатора}{0.9}

    \etotal{15.0}
\end{mse}
```

Здесь энвайронмент `mse` (**M**arking **S**cheme **E**xperiment) — это `tabularx` под прикрытием. В целом, есть следующие команды:

- `\begin{mse}` и `\end{mse}`
- `\escheme{}{}` — стандартный критерий с текстом в первом аргументе и баллом во втором 
- `\blockbegin{}{}{}` — открывает блок марк-схемы (если есть общая тематика: например, построение графика). В третьем аргументе стоит количество требуемых `\bscheme`/`\bremark`, что отражается в количестве выделяемых на это строк в таблице.
- `\blockend`
- `\bscheme{}{}` — то же, что и `\escheme{}{}`, но внутри `\blockbegin...\blockend`.
- `\bremark{}{} — курсивный `\bscheme`.
- `\etotal{}` — завершает таблицу количеством баллов за задачу.

Абсолютно все эти команды указаны в примере выше, так что эта часть, надеюсь, self-explanatory.

### Оформление листов ответов

Если олимпиада требует листы ответов, они все применяются под типом `type=problems` (часто условия задач и листы ответов идут одним комплектом, так что нет смысла добавлять опцию `type=answer`). Оформление идёт в `answer.tex`. Примеры использования:
```
\problem{Стабильность звезды}{10.0}

\part{Параллакс}

\begin{answerbox}{2.5cm}
Формула: \(d=\)

\bigskip

Численное значение: \(d=\)
\end{answerbox}

\part{Формирование протозвезды}

\begin{answerbox}{1.5cm}
\begin{multicols}{2}
\(N=\)

\columnbreak

\(U=\)
\end{multicols}
\end{answerbox}

...
```

```
\subproblem{Переменный (?) ток}{3.5}

\begin{answerboxpart}{6cm}

\textbf{(a)}\vspace{\OlympAnswerGap}

\begin{multicols}{2}

Энергия: \(E=\)

\bigskip

Численное значение: \(E=\)

\columnbreak

Максимальный заряд: \(q_0=\)

\bigskip

Численное значение: \(q_0=\)

\end{multicols}

\vspace{\OlympAnswerGap}
\textbf{(b)}
\vspace{\OlympAnswerGap}

\begin{multicols}{2}

Момент времени: \(t_*=\)

\bigskip

Численное значение: \(t_*=\)

\columnbreak

Заряд: \(q_*=\)

\bigskip

Численное значение: \(q_*=\)

\end{multicols}

\end{answerboxpart}
```
```
\problem{Чёрный пакет}{15.0}

\answersheetwritenumbers

\begin{blankbox}{15cm}
    Уравнения и записи:

    \vspace{7cm}

    Схема ящика:
\end{blankbox}

\newpage

\begin{blankbox}{24cm}
\begin{center}
\emptygridtab{9}{15}
\end{center}
\end{blankbox}

\newpage

% миллиметровка на всю страницу
\begin{blankbox}{25cm}
\begin{center}
\mmgraph{18}{24}
\end{center}
\end{blankbox}
```
Есть основные команды `answerbox{}[]` и `answerboxpart{}[]`. Для `style=ipho` вариант `answerboxpart` не нужен — он, опять же, для солянок респы. В первый, обязательный аргумент входит необходимая высота для данного пункта; нумерация пунктов автоматическая **при условии, что `\problem{...}{...}` и `\subproblem{...}{...}`** были использованы. Во второй, опциональный аргумент, входит количество баллов за данный подпункт (по стандарту респы/IZhO баллы за подпункты не разглашаются, поэтому в примерах выше они отсутствуют).

По стандарту олимпиад не пренебрегайте использованием `\part`, если Вы их использовали в задаче, в тех местах, где это необходимо.

Есть так же `blankbox{}`, у которого есть только один обязательный аргумент о высоте прямоугольника. Нумерация в этом не указана (часто используется для коротких задач, или экспериментов без эксплицитных подпунктов в условии).

Внутри ... не пренебрегайте использованием `\begin{multicols}{2} ... \columnbreak ... \end{multicols}`, или `\bigskip`, или `\vspace{\OlympAnswerGap}`. Команда `\OlympAnswerGap` принимает значение `\FrameSep` — стандартное значение padding внутри прямоугольников.

Команда `\answersheetwritenumbers` генерирует графу, где участник должен написать цифры от 0 до 9. Используется на межнарах для того, чтобы проверяющие могли ссылаться на эту часть, если непонятен почерк в какой-либо части работы.

Команда `\emptygridtab{n}{m}` создаёт пустую таблицу с `n` столбцами и `m` строчками. Полезно для экспериментов.

Команда `\mmgraph{a}{b}` создаёт миллиметровую бумагу шириной `a` сантиметров и высотой `b` сантиметров. Полезно для экспериментов.

#### Использование `scaffolding.py` через `cmd` (стандартная командная строка) на Windows:

1. Нажимаете `Win`, потом прописываете `cmd`, нажимаете `Enter`, чтобы открыть командную строку;

    1. Сначала выбираете шаблон — либо шаблон Респы (`respa`), либо `custom`. Для этого отправляете либо `1` либо `2`;
        - Если выбором будет респа, то задастся вопрос об этапе Респы. По стандарту выбрано, что на респе участвуют 9-11 классы, районный и областной этапы (`raion`, `oblast`) имеют по 4 задачи на класс, заключительный этап (`final`) имеет 1 солянку (`T1A`, `T1B`, `T1C`) и 2 лонга (`T2`, `T3`), в случае `oblast`/`final` создаётся вдобавок экспериментальный тур.
        - Если выбором будет `custom`, то
    2. Следующий вопрос: `What calendar year does this Olympiad's academic year start in (will it be 2025 or 2026, or another year)?`. Для определённости возьмём, что учебный год начинается 1 сентября. Так, если олимпиада проводится в феврале 2026 года, нужно указать `2025`, так как она относится к `2025-26`-ому учебному году.
        - Если Вы выбирали `custom`, то далее как раз и спросится о том, проводится ли олимпиада после 1 января или до (`Is this stage held in the first half of the academic year (autumn, before New Year)? Answer no if it runs from January onward. [y/N]`). Тогда скрипт определит год проведения олимпиады.
        - Если Вы выбирали `respa`, то согласовано, что `raion` проводится в первую половину учебного года, а `oblast`/`final` — во вторую половину. Скрипт определит год проведения сам.
    3. Дальнейшие вопросы касаются только `custom`. Далее нужно будет указать классы проведения: `Grades, comma-separated (e.g. 9,10,11)`. Имейте в виду, что если у Вас нет условного разбиения по классам (например, олимпиада имеет младшую/старшую лиги, или есть только единый комплект), то необязательно даже вводить цифры (например, можно ввести `junior,senior`) — это лишь повлияет на форматирование имён папок и файлов.
    4. `Language codes, comma-separated (e.g. ru,kz)` — в варианте `respa` автоматически используется `ru` & `kz`; можно использовать любые аббревиатуры.
    5. Далее, формат тура. Вводом `1` указываете, что будут теория и эксперимент, с дальнейшими вопросами о количествах задач на каждом туре; вводом `2` будут сгенерированы папки туров `tour1`, `tour2`, ..., причём количество задач для каждого тура уже придётся заполнять Вам.
        - После выбора `1` будут дополнительные вопросы о том, добавлять ли инструкции участникам (для примера см. `shared/example/respa/final/instructions/`), а также добавлять ли answer sheets. При выборе `2` по умолчанию нет инструкций и листов ответов. 
5. Допустим, Вы выбрали `respa_junior` в формате финала (4 задач теории, без эксперимента, 7-8 классы). В результате увидите, что внутри папки `2100-01` будут созданы папки `7/`, `8/`, внутри папки каждого класса будут два языка `ru/` и `kz/`, а также папка `figures/`. И наконец, внутри папки одного из языков, будут лежать задачи в папках `T1/`, `T2`, `T3`, `T4`, а также готовые для компиляции `.tex`-файлы (`theory.tex`, `theory_sol.tex`, ...).
(Убедитесь, что `competitions/config.yaml` имеет информацию о юниорской респе; для этого можете в `config.yaml` переименовать самый верхний уровень из `respa:` в `respa_junior:`)
6. Каждая папка задачи имеет `problem.tex`, `solution.tex`, `marking.tex`, и (необязательно) `answer.tex`. Сюда Вы вставляете все собранные от авторов задачи.

#### `config.yaml` и `manifest.yaml`

Далее, напишите для своей олимпиады собственный `config.yaml`. Файлы `.YAML` удобны тем, что они очень интуитивно понятны для человека, и в этом формате можно хранить мета-данные олимпиады (название олимпиады, имя организатора, и т.д.). За основу используйте `config.yaml` из `example` (однако нельзя переименовывать сам файл, иначе `scaffolding-*.py` **не** увидит `config.yaml`!)

Для олимпиады текущего года напишите `manifest.yaml` (опять же, пример показан в папке `example/`) — это файл, который содержит детали конкретно данного года олимпиады (в какие даты и в каком городе проводится). Это будет обязательно нужно для следующего пункта инструкции.

### 3. Компиляция файлов и использование `strings-*.tex`

#### Введение

Обратите внимание на файлы `*.tex`, `*_sol.tex`, `*_marking.tex`, которые сгенерировались через `scaffolding`. Это — основной костяк для компиляции и превью PDF-файлов. Если работаете в VS Code, то горячей клавишей `Ctrl+Alt+B` можете откомпилировать `.pdf`-файл, который вместе со вспомогательными файлами (`.aux`, `.log`, ...) упадёт в папку `build/`. Чтобы открыть `.pdf`-файл сбоку, нажмите `Ctrl+Alt+V`. Возможно, в терминале будут показаны некоторые warnings, в основном связанные с косметической частью файлов (например, что-то о `Font shape...` или `Overfull \hbox ...`), так что они безвредные.

Однако на данном этапе PDF-файлы будут плохо сгенерированы — если Вы сделаете это прямо сейчас, то увидите, что некоторая часть необходимого текста просто будет пустой. Этот текст нужно внести. Если с мета-данными `config.yaml` и `manifest.yaml` всё в порядке, **за это отвечает `process-strings.py`**.

В `example/` можете увидеть, что есть три дополнительных `string-*.tex` файла, расположенных на разных уровнях. Файл `string-config.tex` нейтрален по отношению к категории олимпиады — скопируйте его к себе и положите в `competitions/`. По надобности добавьте дефинишны своих фрагментов текста — будет удобно содержать все нужные переводы иногда меняющихся текстов в одном месте, чем прыгать по разным файлам и вручную переводить (ведь во всех этих разных файлах, по моей задумке, будут лежать нейтральные к языку команды `\OlympString{...}`).

Файл `strings-competition.tex` лежит внутри папки `respa/`, рядом с папками разных годов — в нём содержится стандартная информация об олимпиаде, независимая от года проведения. Текст берётся из `config.yaml`.

Файл `strings-manifest.tex` уже лежит внутри года олимпиады — здесь содержится всё специфичное к конкретному году олимпиады. Текст берётся из `manifest.yaml`.

#### `process-strings.py`

Чтобы генерировать `strings-*.tex`, для этого написан скрипт `process-strings.py`. В принципе, можно и просто скопировать с `example/` эти три файла, и вручную поменять то, что нужно. Однако с использованием `process-strings.py` можно, в идеале, работать с метаданными только в пределах более читабельных `.YAML` файлов.

1. Повторяете первые два пункта инструкций к `scaffolding-respa.py`;
2. Пишете `python process-strings.py -h` и смотрите на инструкции;
3. Идея в том, что данный скрипт может проверять, все ли `\OlympString{...}` внутри различных файлов (титульная страница, инструкции, колонтитулы) имеют свои верные декларации в виде `\SetOlympString{...}`; а также генерировать шаблонные `string-config.tex` (будет скопировано из `shared/example/` если таков отсутствует), `strings-competition.tex` (на основе `config.yaml`), и `strings-manifest.tex` (на основе `manifest.yaml`). Он также помогает с, например, спряжением слова "задача" или "страница", в зависимости от того, сколько задач и сколько страниц в каждом туре.

Итак, все `strings-*.tex` сгенерированы — можно приступать к генерации PDF-файлов и отправки на олимпиаду.

### 4. Генерация и дистрибуция

Здесь дело малое — вручную откомпилировать все файлы из `*.tex`/`*_sol.tex`/`*_marking.tex`/`*_answer.tex`, пособирать их все из папок `build/`, и отправить ответственному за распечатки человеку.

Да, муторно — поэтому, для этого случая предусмотрен `build.py`:

1. Снова открываете `qazpho-latex/` через командную строку.
2. Прописываете `python build.py compile competitions/<olympiad>/<stage>/<yyyy-yy>` — это по сути сделает `Ctrl+Alt+B` за Вас.
3. Либо, что ещё практичнее, прописываете `python build.py dist competitions/<olympiad>/<stage>/<yyyy-yy>`. Оно сделает всё, что и в предыдущем пункте, но сверху откроет папку `dist/`, перенаправит туда все PDF-файлы из всех `build/`-папок, и переименует все PDF-файлы под нужный формат.
4. Отправляете весь контент `dist/` на распечатку.
5. Имейте в виду, что, при надобности, нужно отдельно сгенерировать `theory_jury.tex` и `experiment_jury.tex` — эти файлы являются внутренним документом для распечатки жюри и использования для того, чтобы красной ручкой по готовым марк-схемам (с дополнительными столбцами для проверки `MP` и апелляции `A`) оценивать каждого участника во время олимпиады.
